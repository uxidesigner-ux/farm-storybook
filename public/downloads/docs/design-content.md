# 문서·접근성 작성 기준

> D03 · 디자인 · 상태: 운영 기준 · 갱신: 2026-11-10

누가 읽어도 현재 상태와 다음 행동을 이해할 수 있도록 문구·표·링크를 작성합니다.

## 제목과 본문을 구체적으로 쓰기

제목은 문서의 목적을 드러내고 본문 첫 문장은 핵심 판단을 설명합니다. 추상적인 수식어를 반복하기보다 관찰한 사실과 적용 조건을 씁니다. 내부 검토안과 고객에게 공개할 표현은 구분합니다.

| 피할 표현 | 권장하는 표현 방식 |
| --- | --- |
| 최고의 프리미엄 채소 | 검증한 품종·맛·규격·사용 상황을 구체적으로 설명 |
| 친환경이라서 건강합니다 | 보유한 인증·재배 기준의 정확한 적용 범위 표시 |
| 바로 드세요 | 실제 세척 상태와 필요한 손질을 명시 |
| 상세 보기 | 연결할 문서나 자료의 목적이 드러나는 링크 이름 |

## 표와 긴 문서의 구조

서로 비교할 항목은 같은 열에 배치하고, 각 행의 관찰 사실과 해석을 섞지 않습니다. 긴 문서는 제목 단계를 순서대로 사용하며 절마다 하나의 질문에 답하도록 나눕니다.

- 표의 빈 값은 0과 구분하고 미확정·해당 없음 등 이유를 씁니다.
- 단위와 기준일은 수치 가까이에 배치합니다.
- 상태는 색상 외에 읽을 수 있는 텍스트로 표시합니다.
- 이미지는 내용을 설명하는 대체 텍스트를 제공하고 장식 이미지는 정보처럼 읽히지 않게 처리합니다.

## 키보드와 작은 화면에서 읽기

검색·필터·링크·다운로드는 키보드로 접근할 수 있어야 합니다. 다이얼로그가 있다면 열고 닫을 때 초점이 예측 가능해야 합니다. 작은 화면에서는 본문을 좁히기보다 탐색과 부가 정보를 순서대로 배치합니다.

## 공유 전 문서 점검

문서의 제목, 상태, 출처와 링크를 함께 확인합니다. 아직 확인하지 못한 항목을 완료로 보이게 하지 않습니다.

- 누가 작성했는지보다 무엇을 근거로 판단했는지 이해할 수 있는가?
- 가설과 확인된 사실의 차이가 문장과 상태에서 드러나는가?
- 출처와 다운로드 링크가 실제 자료를 가리키는가?
- 읽기 순서와 제목 구조가 화면 크기에 따라 유지되는가?

# 주문·재고·채널 연동 검토

> DEV02 · 개발 · 상태: 검토 중 · 갱신: 2026-11-10

브랜드 사이트와 판매 채널의 역할을 나누고 연동 가능성을 실제 조건으로 확인합니다.

## 구매 이동과 시스템 연동을 구분하기

브랜드 사이트에서 외부 판매 페이지로 이동하는 기능, 자체 사이트에서 주문을 받는 기능, 여러 채널의 주문·재고를 자동 동기화하는 기능은 각각 다른 범위입니다. 네이버 결제와 쿠팡 등 여러 채널의 자동 연동을 하나의 기능처럼 가정하지 않습니다.

## 세 가지 구현 범위

아래 표는 선택지 비교이며 지원 가능 여부를 확정한 기술 명세가 아닙니다.

| 방식 | 사이트의 역할 | 검토할 운영 조건 |
| --- | --- | --- |
| 외부 구매 연결 | 브랜드·상품 설명과 판매 페이지 이동 | 채널별 상품 URL · 가격 일치 · 이동 측정 |
| 자체 주문·결제 | 주문 접수 · 결제 · 상태 안내 | 계약 · 정산 · 취소·환불 · 고객 대응 |
| 여러 채널 통합 | 상품·주문·재고 데이터 동기화 | 지원 API · 권한 · 비용 · 갱신 지연 · 오류 복구 |

## 수확과 판매 가능량의 기준

농산물의 판매 가능량은 총 생산량과 같지 않을 수 있습니다. 선별 완료량, 포장 가능량과 출고 처리량을 확인한 뒤 판매 수량을 정합니다. 예약 판매라면 예상량과 확정량을 구분하고 변동 시 고객 안내 기준을 마련합니다.

## 개발 전에 확인할 항목

선택한 플랫폼의 최신 공식 문서와 판매자 계정 조건을 기준으로 지원 범위를 확인합니다. 테스트 환경에서 가능한 동작과 실제 운영 권한을 구분합니다.

- 어떤 시스템의 상품·재고·주문 정보를 기준으로 삼는가?
- 업데이트가 실패하거나 늦어졌을 때 누가 확인하는가?
- 중복 주문과 품절 이후 주문을 어떻게 처리하는가?
- 취소·환불·대체 출고의 상태를 어디에서 관리하는가?
- 개인정보와 고객 문의를 처리하는 책임이 누구에게 있는가?

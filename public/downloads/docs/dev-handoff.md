# 개발 인수인계와 완료 기준

> DEV03 · 개발 · 상태: 초안 · 갱신: 2026-11-10

문서·디자인·구현의 차이를 줄이기 위한 요청 형식과 검증 기준입니다.

## 요청에 함께 전달할 것

개발자는 최신 화면뿐 아니라 동작의 이유와 조건을 확인할 수 있어야 합니다. 기능 정의, 화면과 컴포넌트 예제, 정책, 데이터와 예외를 같은 문서 ID로 연결합니다.

## 검증 가능한 완료 기준

완료는 화면이 보이는지뿐 아니라 고객이 목적을 끝낼 수 있는지로 판단합니다.

| 대상 | 확인 예시 |
| --- | --- |
| 상품 상세 | 규격·상태·가격·구매 동선이 실제 상품 데이터와 일치 |
| 검색·필터 | 입력과 선택에 맞는 결과, 결과 없음과 초기화 동작 제공 |
| 문서 탐색 | 직접 URL 접근 · 새로고침 · 뒤로 가기에서 내용 유지 |
| 다운로드 | 표시된 파일과 실제 파일 형식·내용이 일치 |
| 공유 | 공유 URL이 특정 문서나 예제를 가리킴 |
| 반응형 | 작은 화면에서 본문·표·탐색의 핵심 사용 가능 |

## 예외를 정상 흐름과 함께 정하기

빈 결과, 긴 문구, 출처 링크 실패, 다운로드 불가 등 예상 가능한 상태를 정의합니다. 판매 기능은 품절, 출고 변경과 결제 결과의 실제 계약·운영 조건을 확인한 뒤 다룹니다. 임의의 성공 상태로 실패를 감추지 않습니다.

## 변경과 확인의 기록

수정 범위에 맞는 확인을 수행하고 결과를 남깁니다. 모든 변경에 같은 규모의 검증을 반복하기보다 남은 위험을 해결하는 확인을 선택합니다.

- 변경 이유와 영향을 받는 화면·문서
- 검증한 시나리오와 실제 결과
- 검증하지 못한 조건과 남은 결정
- 관련 브랜치·커밋·배포 버전의 연결

# 토큰과 컴포넌트 사용법

> D02 · 디자인 · 상태: 초안 · 갱신: 2026-11-10

화면별 꾸밈을 늘리기보다 역할이 같은 요소의 표현과 상태를 함께 관리합니다.

## 역할을 이름으로 관리하기

토큰은 색상 값 자체보다 역할을 드러내는 이름으로 관리합니다. 본문색, 보조 텍스트, 표면, 구분선, 주요 행동과 상태 표현을 나눕니다. 실제 값과 구현은 컴포넌트 예제와 코드에서 확인하며, 이 문서의 기준과 함께 갱신합니다.

## 기본 요소의 책임

같은 역할은 같은 컴포넌트를 사용하고, 변형이 필요한 이유를 문서화합니다.

| 요소 | 역할 | 함께 정의할 상태 |
| --- | --- | --- |
| 버튼 | 실행할 행동 표시 | 기본 · 호버 · 초점 · 비활성 · 처리 중 |
| 문서 카드 | 내용과 상태를 미리 설명 | 제목 길이 · 태그 · 상태 · 링크 |
| 상태 배지 | 문서의 성숙도 표시 | 리서치 완료 · 검토 중 · 초안 · 운영 기준 |
| 콜아웃 | 본문의 조건과 핵심 전달 | 근거 · 가설 · 주의 · 결정 |
| 표 | 같은 기준의 비교 | 긴 셀 · 좁은 화면 · 빈 값 |
| 탭·필터 | 보이는 정보 범위를 조절 | 선택 · 초점 · 결과 없음 |

## 예제는 현실적인 길이와 내용을 사용하기

짧은 영문 예제만으로 한국어 문서의 동작을 판단하지 않습니다. 긴 제목, 여러 태그, 출처가 없는 문서, 모바일의 긴 표를 함께 확인합니다. 판매 상품을 보여주는 예제에서는 미확정 가격이나 효능을 사실처럼 넣지 않습니다.

## 컴포넌트 변경의 확인 기준

변경은 의미·접근성·시각 일관성에 대한 영향을 확인한 뒤 반영합니다.

- 마우스와 키보드로 같은 핵심 작업을 수행할 수 있습니다.
- 초점 위치와 현재 선택이 화면에서 확인됩니다.
- 문구가 길어져도 핵심 정보나 행동이 잘리지 않습니다.
- 실제 사용하는 변형과 예제가 문서에 함께 남습니다.

# 문서 상태와 결정 기록

> OPS03 · 운영 · 상태: 운영 기준 · 갱신: 2026-11-10

확인한 사실과 가설, 현재 적용하는 기준을 구분해 같은 문서를 보고 협업합니다.

## 상태는 문서의 성숙도를 나타내기

상태는 사업 전체의 진행률이 아니라 해당 문서를 어떻게 읽어야 하는지 설명합니다. 리서치가 완료됐더라도 그 결과로 제안한 전략이 확정된 것은 아닙니다.

| 상태 | 의미 | 독자가 할 일 |
| --- | --- | --- |
| 리서치 완료 | 표시된 범위·기준일의 조사와 정리 완료 | 관찰 사실과 한계를 확인 |
| 검토 중 | 대안이나 선택 조건을 논의하는 단계 | 근거·조건·결정 필요 항목 검토 |
| 초안 | 첫 구조와 내용이 작성된 단계 | 누락·실행 가능성·표현 피드백 |
| 운영 기준 | 현재 문서 공간에서 적용할 작업 기준 | 해당 기준으로 작성·검토 |

## 결정에 남길 내용

결정에는 문제, 선택지, 판단 근거, 결정 내용, 적용 범위, 책임자, 날짜와 재검토 조건을 기록합니다. 결과만 남기면 이후 조건이 바뀌었을 때 왜 선택했는지 알기 어렵습니다.

> **기록 템플릿**
> 결정할 문제 / 검토한 대안 / 확인한 증거 / 선택한 방향 / 적용 범위 / 책임자·날짜 / 다시 검토할 조건

## 직군별 확인 책임

담당자 이름이 확정되지 않은 영역은 직군과 필요한 역량을 먼저 기록합니다. 프로젝트 제안 단계의 담당 표기와 실제 배정은 구분합니다.

| 영역 | 필요한 확인 역량 |
| --- | --- |
| BX·기획 | 고객 조사 · 포지셔닝 · 경험 설계 |
| 디자인 | 정보 구조 · 시각 체계 · 패키지·UI 제작 |
| 개발 | 웹 구현 · 데이터·연동 검토 · 품질 확인 |
| 농가·운영 | 재배·선별 · 포장·출고 · 고객 대응 |
| 마케팅 | 메시지 · 콘텐츠 제작 · 실험·측정 |

## 수정할 때 연결 문서도 갱신하기

상품의 규격·가격·출고 기준처럼 여러 접점에 쓰이는 결정은 한 곳을 기준 정보로 정합니다. 변경 시 상세페이지, 포장, 마케팅 문구와 개발 명세의 영향을 함께 확인합니다.

- 기준일은 실제 내용 확인 또는 수정 시점으로 갱신합니다.
- 출처가 바뀌면 관련 주장과 상태도 다시 검토합니다.
- 폐기한 가설은 삭제만 하지 말고 결정 이유를 기록합니다.
- 외부 공유본과 내부 검토본의 내용 차이가 있으면 명시합니다.

# 문서 추가와 공유 절차

> DEV04 · 개발 · 상태: 운영 기준 · 갱신: 2026-11-10

새 산출물을 같은 구조로 기록하고, 변경 근거와 공유 범위를 함께 관리합니다.

## 설명과 실행 예제를 한곳에

이 문서 공간은 전략·가이드와 실제 UI 예제를 연결하기 위한 장소입니다. 문서에는 의도와 기준을, 컴포넌트 예제에는 동작과 변형을 기록합니다. 같은 내용의 사본을 여러 곳에 유지하기보다 원본과 연결합니다.

## 문서에 필요한 메타데이터

문서 데이터는 content/guide-data.json의 구조를 기준으로 관리합니다. 새 문서는 고유 ID를 사용하고 기존 문서의 ID를 제목 수정 때문에 바꾸지 않습니다.

| 항목 | 작성 기준 |
| --- | --- |
| id | 변경에 안정적인 고유 식별자 |
| category · title · summary | 분류 · 목적이 드러나는 제목 · 한 문장 요약 |
| status · updatedAt | 현재 성숙도 · 내용 확인 또는 수정 기준일 |
| tags · sections | 검색어 · 제목 단계에 따른 본문 구조 |
| sources | 공식 자료 이름과 실제 URL |

## 업데이트 순서

새 콘텐츠를 작성한 뒤 출처·상태·링크와 화면을 확인하고 변경 이유를 남깁니다. 저장소의 실제 배포 설정에 따라 사이트를 갱신합니다. 계정 연결과 배포 권한이 확인되지 않은 상태를 게시 완료로 표시하지 않습니다.

- 기존 문서와 중복되는지 확인하고 추가·수정 범위를 정합니다.
- 작업 브랜치를 채번한 뒤 문서와 예제를 함께 수정합니다.
- 본문·링크·다운로드·직접 공유 주소를 확인합니다.
- 저장소 반영과 공개 범위는 프로젝트의 승인 기준에 따라 진행합니다.

## 링크와 공개 범위

특정 문서를 가리키는 링크와 외부 사용자에게 접근 권한을 부여하는 행위는 다릅니다. 공유 전에 사이트의 현재 접근 범위와 문서에 포함된 정보의 공개 가능 여부를 확인합니다. 초안 문서도 상태가 분명하면 검토용으로 공유할 수 있습니다.
